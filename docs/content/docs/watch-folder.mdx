Desktop opens it.

| Folder | What it holds |
| --- | --- |
| `input/` | Recordings to shrink. |
| `output/` | The results. |
| `.processed/` | Hidden. Originals after a good encode. |
| `.logs/` | Hidden. The log, `optimizer.log`. |

## What happens to a recording

The watcher is a launchd agent that runs shrinkit when `input/` changes and at login. A run takes
the `.mov`, `.mp4` and `.m4v` files straight inside `input/`, and skips hidden files and folders.
For each one:

1. An empty file is skipped. A file whose size changes over two seconds is still being written, so
   it is skipped too. A later run takes it: the next drop into `input/`, or `shrinkit` with no file
   names.
2. It is encoded with [`settings.conf`](/docs/settings/) into `output/`, under the
   [result name](/docs/right-click/#result-names) rule: `clip.mov` gives `output/clip.mp4`.
3. With `keep_original = true`, the default, the original moves to `.processed/`. With `false` it
   is deleted.

Each file posts the same [banners](/docs/settings/#banners) as a right-click run.

`shrinkit` with no file names does the same as the watcher, and takes the setting flags:
`shrinkit --crf 32`. `--cut` and `--keep` need a file name.

## Originals

[`keep_days`](/docs/settings/) deletes originals from `.processed/` after a number of days; by
default they stay. A file put back into `input/` is shrunk again.

## When a recording fails

A recording that cannot be shrunk stays in `input/` and is tried again on every later run. A banner
says `Could not shrink`, and `.logs/optimizer.log` has ffmpeg's output.

A recording that was shrunk but could not be moved or deleted also stays in `input/`. Its result is
in `output/`, and later runs skip it.

[`shrinkit doctor`](/docs/troubleshooting/) names both kinds.
